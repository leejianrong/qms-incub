# synthetic-corpus

Independent tool that generates a fixed golden set of realistic
QMS-policy-shaped PDFs on local disk, so you can manually exercise the
backend's ingestion/RAG pipeline without any real, sensitive QMS content.
It shares no code with `backend/` and never calls it over HTTP — its job
ends at "PDFs exist on disk" (ADR-0012, `docs/adr/`).

## 1. Generate the PDFs

```bash
cd synthetic-corpus
uv sync
uv run python scripts/generate.py
```

This loads the 10 committed documents in `documents/*.json` and renders
each to `output/*.pdf` (gitignored — regenerated on demand from the
committed JSON, so nothing here needs to be regenerated byte-identically).

## 2. Start the web app

From the repo root, follow the main [README](../README.md#quick-start)'s
Quick Start: `make up` gets Postgres, Qdrant, the backend, and the
frontend (`:5173`) running. The backend normally listens on `:8000`, but
if something else on your machine already owns that port, `make up`
detects it and falls back to `:8001` (then `:8002`, ...) automatically —
watch its output for a line like `Backend will run on port 8001 (8000
was busy)`, and use that port in step 3 below instead of 8000. It also
wires the frontend's `VITE_API_BASE` to match, so the chat panel at
`:5173` keeps working either way.

## 3. Upload the golden corpus

With the backend up, upload every generated PDF through the real
`POST /documents` endpoint (the same path `make seed` uses for the V1
demo fixture). Replace `8000` below with whatever port `make up` printed
if it had to fall back:

```bash
for f in synthetic-corpus/output/POL-*.pdf; do
  curl -sf -F "file=@$f" http://localhost:8000/documents
done
```

Each call returns `{"id": ..., "status": "embedded", "chunk_count": ...}`
once Docling has parsed, chunked, and embedded that document into Qdrant.

## 4. Ask it questions

Open http://localhost:5173 and ask questions in the chat panel, or call
the API directly:

```bash
curl -s -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"question": "..."}'
```

A good first question — it requires following a cross-reference between
two different documents rather than answering from just one:

> If a proposed change requires provisioning new access to a system
> storing Confidential data, which policies apply and what does each one
> require?

(Expects an answer combining the Access Control and Least Privilege
Policy, POL-006, with the Data Classification and Handling Policy,
POL-007.) See
[`docs/shaping/synthetic-doc-realism/RAG-SPOT-CHECK.md`](../docs/shaping/synthetic-doc-realism/RAG-SPOT-CHECK.md)
for the full fixed question list and the results from the last manual
spot-check.

## Corpus contents

- `domain-profile.json` — the business function this corpus is for
  (roles, policy topics, standards bodies to cite). Extending to a new
  domain (HR, finance, legal...) means authoring a new profile, not
  touching any code.
- `corpus-plan.json` — the 10 documents' IDs, titles, topics, and which
  other doc IDs each one is planned to cross-reference, decided up front
  so citations are correct by construction.
- `documents/*.json` — the actual block-model content for each of the 10
  documents (prose, tables, flowchart/swim-lane diagrams).

See
[`docs/shaping/synthetic-doc-realism/`](../docs/shaping/synthetic-doc-realism/)
for this tool's own planning docs (FRAME/SHAPING/SLICES).
